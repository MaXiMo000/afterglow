# Design

## 1. Product
Input: a public `github.com/<owner>/<repo>`. Output: a scroll story, then a free-fly city, and a short list of useful
engineering insights.

| Visual | Meaning | Insight it supports |
| --- | --- | --- |
| Building | A file. Height = size (lines) | Where the mass of the codebase is |
| Lit windows | Recent activity (recency-weighted) | What is alive |
| Red beacon | Hotspot: high churn, few authors | Where regressions start |
| Dark, fogged district | Untouched for years | Code nobody dares touch |
| Lanterns | Contributors, roaming files they worked on | Who knows what |
| Arcs between districts | Co-change coupling | Hidden dependencies |
| Time scrubber | Whole history replayed | How the codebase grew and decayed |
| Bus factor per district | Fewest people covering half the commits | Knowledge risk |

Insights panel: hotspots, bus factor, quiet zones, coupling pairs, growth timeline, compare two dates.

## 2. Architecture
```
Browser (static SPA) --https--> Caddy (TLS, CSP and headers, static files, body cap)
                                  |  /api/*
                                FastAPI API (never runs git; internal network)
                                  |  Postgres: jobs queue (SKIP LOCKED) + validated results
                                Worker (separate image and network, sandboxed) --> egress proxy --> github.com:443 only
```
- API never runs git; the worker never serves traffic. Separate images, users and networks; no shared volumes.
- Results are immutable, keyed by `owner/repo@sha` + analyser version, schema-validated on write and read, served as
  JSON with `ETag` and `Cache-Control: immutable`.
- Private repositories are not supported.

## 3. Tech decisions
| Decision | Reason |
| --- | --- |
| Python 3.12, FastAPI, Pydantic v2, uvicorn | Strict typed schemas at the boundary |
| Worker parses `git log --name-status -z` from a bare, blobless clone; line counts from one capped, batched fetch of HEAD's blobs, never checked out | Attacker-controlled files are never written to disk; lazy per-blob fetches would be slow and uncappable |
| Queue: Postgres `SELECT ... FOR UPDATE SKIP LOCKED` | One stateful service for jobs and results |
| Result wire format: strict JSON, compressed by Caddy | Measured 62.5 KB gzip for 3,139 files, ~1 MB at the 50k-file cap (budget 1.5 MB) |
| Vite + TypeScript strict, no UI framework; raw WebGL2 renderer | Small bundle (a scene library would add ~150 KB gzip); GPU picking and parallel shader compile need raw GL anyway |
| Lenis behind our own `ScrollEngine`; own small timeline and spring helpers | Replaceable; no animation-library weight |
| Fonts self-hosted, every face `font-display: optional` and preloaded | No third-party origins; a late swap re-wrapped the hero title (CLS 0.29) |
| GPU picking via an ID buffer | O(1) hover cost at any file count |
| 2D treemap + table fallback | No-WebGL devices, screen readers, print |
| Metrics: hotspot = >= 5 changes in the 12 months before HEAD by <= 3 authors (top 20); quiet = no change in 2 years; bus factor = fewest authors covering >= 50% of commits in a district; coupling = co-changes / min(changes) over the latest 10k commits, ignoring commits touching > 20 files, min 3 | No file contents needed. Bus factor is commit-weighted, not line-weighted, and the UI says so |
| Time reference is HEAD's commit time, not wall-clock | Results are reproducible and cacheable by sha |
| Districts = top-level directories; one holding more than half the files is split a level deeper | Monorepos still get useful districts |
| Compare mode shows files at HEAD only (removed files are not in the result) and says so | Uses only per-file birth and last change |
| Effects by tier: simple has no DOF/flare; balanced adds cheap DOF + flare; cinematic adds god rays + MSAA. Motion effects are off under reduced motion | Low tier stays cheap; effects degrade gradually |
| Dynamic resolution: healthy = frame interval at or under the refresh interval; step up after ~10 s steady | rAF intervals never go below 16.7 ms at 60 Hz |
| Visual regression: Linux-only baselines generated by CI and gated; the WebGL canvas is hidden in snapshots | GPU output is not pixel-stable across drivers |
| Accessibility gate: axe (WCAG 2.2 A/AA) in every UI state, tab order, focus return, reduced motion | Regressions fail CI |
| Release: tag-only workflow; images on GHCR pinned by digest; CycloneDX SBOMs; Sigstore build provenance | Supply chain (SECURITY T16) without new services |
| Privacy: the client pseudonym is cleared by a DB trigger when a job ends; logs are size-capped | Data minimisation enforced in one place |

## 4. API (v1)
- `POST /api/v1/analyses` body `{"repo":"owner/name"}`, headers `Content-Type: application/json` and `X-Afterglow: 1`
  -> `202 {"id","status":"queued"}` (new or deduplicated) or `200 {"id","status":"done"}` if a fresh result exists.
  Errors: `400 invalid_repo`, `403 forbidden`, `413 too_large`, `415`, `429 rate_limited|too_many_jobs`,
  `503 busy` (+ `Retry-After`). Repo regex `^[A-Za-z0-9-]{1,39}/[A-Za-z0-9._-]{1,100}$`, not `.`/`..`, no URLs.
- `GET /api/v1/analyses/{id}/events` -> SSE frames `{"status","stage","n","total"[,"reason"]}`; stages
  `queued, cloning, counting, parsing, sizing, scoring, done, failed`.
- `GET /api/v1/analyses/{id}` -> `200` result, `409 not_ready`, `422 <reason>` for failed jobs, `404` unknown.
  Ids are 32 lower-case hex characters (random UUIDv4).
- Result schema (strict, `extra=forbid`, bounded): `meta{repo,sha,analyser,generated_at,commits,files,people,span,truncated}`,
  `dirs[]`, `files[]`, `coupling[]`, `people[] {handle,commits,areas}`, `insights{hotspots,bus_factor,quiet,coupling}`,
  `timeline[]`. Contributors are pseudonyms (`Contributor 7`); emails are never read.
- Hard caps (tested): pack size, commits (200k), files (50k), path length, wall time (90 s), memory, output size.
  Over a cap the most recent data is analysed, `truncated` is set, and the UI says so.

## 6. Budgets (requirements; measurements in `docs/PERF-LOG.md`)
| Metric | Budget |
| --- | --- |
| Initial JS gzip (landing + renderer) | <= 400 KB |
| Time to first rendered frame | <= 2.5 s on a mid-range Android, 4G |
| Frame rate | 60 fps desktop and recent phones; >= 30 fps on the reference low-end phone |
| Input latency | camera follows the smoothed scroll value within 1 frame; smoothing settles in <= 150 ms; INP < 200 ms |
| Draw calls | <= 60 low tier, <= 150 high; buildings instanced |
| Result payload | <= 1.5 MB gzip for a 50k-file repo |
| JS heap | <= 300 MB; no growth over a 10-minute soak |
| Layout shift | CLS 0 |
| Idle | Render at low rate or stop when nothing moves; stop when the tab is hidden |

Reference low-end device: a 2023 budget Android phone class (Mali-G57 / Adreno 610, 4 GB RAM, Chrome), e.g. Galaxy A14.
Not yet measured on hardware.
